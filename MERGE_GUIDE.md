# Task 2 Integration and Merge Guide

This document explains how to merge **Task 2 (Sensitivity & Crafting Service)** into the main team GitHub repository and how it interfaces with the other 9 subparts of the **Shadow Citadel Raid Optimizer**.

---

## 1. Overview of Task 2

In the 10-part project architecture:
* **Part 1 (Pair Partner)**: Hand-crafted Simplex, Big-M, and Two-Phase engine (`simplex.py`, `bigm.py`, `twophase.py`).
* **Part 2 (Your Task)**: Sensitivity analysis (`sensitivity.py`) and the Crafting REST API (`api/api_craft.py`).
* **Part 5 (Pipeline & App Root)**: Chaining the TSP route time into crafting time limit ($120 - \text{tour\_time}$), mounting all FastAPI routers in `app.py`.
* **Part 9 (Frontend Partner)**: Loadout tab with tableau stepper, sliders, shadow price charts, and bottleneck banner.

## 3. How to Merge with Specific Parts

### A. Merging with Part 1 (`solvers/`)
* **Files involved**: `solvers/simplex.py`, `solvers/bigm.py`, `solvers/twophase.py` (Part 1) and `solvers/sensitivity.py` (Part 2).
* **Connection**: 
  * Part 2's `shadow_prices` and `rhs_ranging` read the `steps[-1]` tableau snapshot generated by Part 1.
  * Constraint naming convention:
    * Slack variables: `s1`, `s2`, `s3`
    * Surplus & Artificial variables: `e4`, `a4`
    * Equality Artificial variables: `a5`
  * Both parts import `from envelope import envelope`.

### B. Merging with Main FastAPI App (`app.py` / Part 5)
In the main FastAPI entrypoint (usually `app.py` or `main.py`), Part 5 mounts all endpoints. Ensure the crafting router is registered:
```python
from fastapi import FastAPI
from api.api_craft import router as craft_router

app = FastAPI(title="Shadow Citadel Raid Optimizer")

# Include the Crafting endpoint
app.include_router(craft_router, prefix="/api", tags=["Crafting"])
```
This exposes `POST /api/craft`.

### C. Merging with Pipeline (`pipeline.py` / Part 5)
Part 5 chains the route tour time into the crafting stage:
```python
from api.api_craft import CraftRequest, post_craft

# 1. Tour time from Stage 2 (TSP)
tour_time = 70.0  # optimal tour in demo
craft_time_available = max(0.0, 120.0 - tour_time)  # 50.0 min

# 2. Call Part 2 crafting solver
craft_req = CraftRequest(
    time_limit=craft_time_available,
    recipes=scenario["recipes"],
    limits=scenario["limits"],
    method="bigm"
)
craft_res = post_craft(craft_req)

if craft_res["status"] == "optimal":
    crafting_score = craft_res["answer"]["z"]      # 117
    total_score = combat_score + crafting_score     # 445 + 117 = 562
else:
    # Handle infeasible case (e.g. naive 80 min tour leaving only 40 min)
    crafting_score = None
    total_score = None
```

### D. Merging with Frontend Tab (Part 9 - Loadout Tab)
* Part 9 calls `POST /api/craft` with the JSON payload.
* The frontend reads:
  * `response.answer.z`: Displayed in score badge ($117$).
  * `response.answer.x`: Values for $x_1, x_2, x_3, x_4$ ($[7, 0, 4, 3]$).
  * `response.answer.shadow_prices`: Rendered as a bar chart ($0.75, 0.50, 4.25$).
  * `response.answer.bottleneck`: Highlighted banner text.
  * `response.steps`: Fed into the shared `StepPlayer` component for step-by-step pivoting playback.

Run these commands before merging:

```bash
# 1. Run Part 2 sensitivity tests
pytest test_part2_sensitivity.py -v

# 2. Run API endpoint tests
pytest tests/test_craft_api.py -v

# 3. Run contract check
pytest -k craft
```

All tests should show green (`PASSED`).

## 5. Resolving Merge Conflicts

If Git flags a conflict in `app.py`:
1. Open `app.py` in your editor.
2. Look for conflict markers `<<<<<<<` and `>>>>>>>`.
3. Keep other team members' router imports (e.g., `hull_router`, `route_router`, `assign_router`) and keep `craft_router`.
4. Run `git add app.py` and `git commit -m "chore: resolve router merge conflict"`.
